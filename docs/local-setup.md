# FactoryAssist AI — Local Setup

This guide runs FactoryAssist on a developer machine using **Ollama + Qwen2.5**, **FAISS**, **FastAPI**, **Gradio**, and **LangGraph**. The same application code also supports cloud deployment; see [Azure Deployment](azure-deployment.md).

## 1. Requirements

- Python **3.11** and [`uv`](https://docs.astral.sh/uv/)
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) with Docker Compose
- [Ollama](https://ollama.com/)
- Enough free disk space for the embedding model, Python dependencies, and Docker images
- Optional: Langfuse account for traces and quality scores

On Apple Silicon, run Ollama **on macOS**, not inside the application containers. Docker connects to it through `host.docker.internal`.

## 2. Clone and configure

```bash
git clone <YOUR_GITHUB_REPOSITORY_URL>
cd factoryassist-ai
uv sync --locked
cp .env.example .env
```

Set the following in `.env`:

```dotenv
MODEL_PROVIDER=ollama
OLLAMA_MODEL=qwen2.5:1.5b
OLLAMA_BASE_URL=http://127.0.0.1:11434
DOCUMENT_SOURCE=local
INDEX_SOURCE=local
FAISS_INDEX_PATH=artifacts/faiss
MAX_QUESTION_TOKENS=256
MAX_CONTEXT_TOKENS=2000
MAX_INPUT_TOKENS=3000
MAX_OUTPUT_TOKENS=384
```

If using Langfuse, add `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, and `LANGFUSE_BASE_URL` to your **private** `.env`. Do not commit `.env` or real credentials.

## 3. Start the local LLM

Install/start Ollama, then run:

```bash
ollama pull qwen2.5:1.5b
ollama list
curl http://127.0.0.1:11434/api/tags
```

The response should list `qwen2.5:1.5b`. The model runs locally; it does not require a Groq or Azure OpenAI key.

## 4. Build the local FAISS index

The repository contains **synthetic** manufacturing documents in `data/`. Build the index once (and again when documents or embeddings change):

```bash
DOCUMENT_SOURCE=local uv run python -m factoryassist.rag.ingestion
ls -lh artifacts/faiss/
```

Expected index files: `index.faiss` and `index.pkl`. Query embeddings and indexed document embeddings must use the same model, currently `sentence-transformers/all-MiniLM-L6-v2`.

Check retrieval independently:

```bash
INDEX_SOURCE=local uv run python -m factoryassist.rag.retriever
```

**Security:** LangChain's FAISS loading uses Python pickle metadata. Only load indexes generated by this project's trusted ingestion process; never deserialize arbitrary `.pkl` files.

## 5. Run using Docker Compose (recommended)

The application has two services: `api` (FastAPI) and `ui` (Gradio). Ollama stays on the Mac.

```bash
docker compose config --quiet
docker compose build
docker compose up -d
docker compose ps
```

In `compose.yaml`, the API uses `OLLAMA_BASE_URL=http://host.docker.internal:11434` and mounts `./artifacts/faiss` into the container. The UI calls the API over the Compose network using `FACTORYASSIST_API_URL=http://api:8000/ask`. Gradio must listen on `0.0.0.0` **inside** its container.

Open:

- Gradio: <http://127.0.0.1:7860>
- FastAPI docs: <http://127.0.0.1:8000/docs>
- API health: <http://127.0.0.1:8000/health>

Try: **“What causes error E-2047 in machine M-204, and how should maintenance personnel respond?”** The answer should cite retrieved source IDs and list source paths.

Inspect services and logs:

```bash
docker compose logs --tail=60 api
docker compose logs --tail=60 ui
docker stats --no-stream
```

Stop without deleting your local FAISS index:

```bash
docker compose down
```

## 6. Run directly with uv (optional)

When running outside Docker, keep `OLLAMA_BASE_URL=http://127.0.0.1:11434`. In separate terminals:

```bash
uv run uvicorn factoryassist.api.main:app --host 127.0.0.1 --port 8000
```

```bash
uv run python -m factoryassist.ui.gradio_app
```

The default Gradio API URL is `http://127.0.0.1:8000/ask`.

## 7. Tests and evaluation

```bash
uv run pytest -q
```

The project includes retrieval evaluation and Langfuse quality scoring. Evaluation figures reported in the main README should identify their dataset, settings, and limitations. Langfuse traces are available when valid credentials are configured.

## 8. Troubleshooting

| Symptom | Check |
|---|---|
| Gradio opens but cannot reach API | `docker compose ps`, UI logs, and `FACTORYASSIST_API_URL` |
| Ollama connection fails from Docker | Ollama running on Mac; `OLLAMA_BASE_URL=http://host.docker.internal:11434` |
| FAISS index missing | Run ingestion; verify `artifacts/faiss/index.faiss` and `index.pkl` |
| First query is slow | Initial embedding-model loading and LLM inference can take time |
| Docker image is large | PyTorch/SentenceTransformers dependencies; use CPU-only Linux wheels |
| No Langfuse traces | Verify private credentials and endpoint |

## 9. Configuration portability

The **FastAPI/LangGraph workflow** selects its model through `MODEL_PROVIDER` and its index through `INDEX_SOURCE`. Local mode uses `ollama` + `local`; cloud mode uses `groq` + `azure`. This is one codebase, not two separate RAG implementations.

The standalone `factoryassist.rag.pipeline` demonstration may have different model-initialisation behaviour; the API's primary workflow is `factoryassist.orchestration.graph.run_workflow`.
